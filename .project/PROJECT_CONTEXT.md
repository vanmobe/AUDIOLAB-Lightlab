# Lightlab — project context

## Purpose

Local-first web application for designing, simulating and eventually operating small-stage light shows. The application is a show editor and simulator first; a hardware runtime is introduced through explicit adapters.

Status audit2026-09-14: this describes the current implementation, NOT a reduced product scope or completion. Full target still includes native audio/Dante, MIDI/WING transport, runtime timing and show-to-multi-universe DMX, verified fixture encoders/import, minimum lit-fixture coverage, richer color roles, complete AI request/response inspection, durable portable show/version management and cross-platform delivery. See `docs/REVIEW_2026-09-14.md` for accepted findings, deferred work and evidence.

Current user priority: continuous sACN/Art-Net show output is now requested and implemented as explicit runtime opt-in. Physical WING/MIDI and audio/Dante remain open. `docs/NETWORK_OUTPUT.md` is authoritative for the new output behavior and supersedes historical memory-only/no-show-transmission notes below; `docs/CREATIVE_DAILY_USE.md` records creative work separately.

## Confirmed constraints

- Product name: Lightlab, by Audiolab. Visual reference: https://co-lab.eu/audiolab/ (charcoal, white, blue #2f7cff accents, restrained typography). Keep local-first operation; no external font requests. The legacy lightflow storage/package identifiers remain stable for saved-show compatibility. Product branding must not rename users' shows.
- UI shell uses locally bundled Mulish and Syncopate fonts (licenses in `public/fonts`) and a shared nine-rounded-bar light-spectrum SVG mark (`public/favicon.svg`), preserving the two-peak rhythm of Audiolab's waveform logo rather than a separate L monogram; shared visual rules live in `lightlab.css`. Audiolab blue, mint and orange accents distinguish workspaces without recoloring fixture types, group rings or simulated light. Use darker primary fills for white text contrast. Keep spatial map handles outside generic button geometry. Start is a data-driven ShowDashboard, not a marketing page. The Show disclosure provides file/version actions in every workspace; reset confirms and persists a recovery version before mutation. Import explicitly confirms replacement of current show/history.
- App owns workspace departure; PatchWorkspace reports dirty state without changing the show. Canceling departure preserves draft values. This guard does not protect browser reloads. LiveLookLibrary keeps Look rows compact, adds search above six items and discloses active-Look composition; direct group masters are a secondary disclosure whose saved-versus-preview distinction must remain visible.

- The browser simulator is the initial active output. It must not send network DMX by default.
- Viewer haze is a bounded 0..100 local preference (default35) in shared SimulationSettings, not show/DMX state. Constant scene fog and soft beams model haze; a shared two-scale world-space noise shader creates drifting plume structure without particles/extra draws. The renderer-owned time uniform is independent of BPM, freezes for hidden/zero-size views and reduced motion, and bounds resumed frame gaps. Zero haze hides beam volumes but retains surface lighting. Emissive beam/lens materials exclude fog tint. Missing haze on older direct renderer callers follows evaluated hazer output; App always supplies its viewer preference. No measured photometry, fluid simulation or position-based hazer emission claim.
- Physical DMX patching is edited in the app: fixture, universe, address and a single protocol route (Art-Net or sACN) per output universe.
- Console support is vendor-neutral. Behringer WING Rack, Full and Compact are the first capability profiles.
- Audio can come from a direct feed (including Dante/WING); MIDI backing-track cues change persistent show state. Tap tempo and MIDI clock are optional fallbacks.
- Color profiles and automation programs are independent; Looks combine them. Defaults are 8 profiles, 8 programs and 16 Looks, with a maximum of 32 per type.
- Initial fixture inventory: 12 ADJ Mega TriPar Profile Plus, 1 Stairville Hz-200 Compact Hazer DMX, 2 Stairville Stage TRI LED Bundle Complete, 4 Varytec LED Theater Spot 100 3000K.

Providers receive validated profile plus derived guidance, never physical routing. Explicit preferences override genre associations; no lookup/assumptions from band name.
- Band limits affect generated output only: recipe steps simple≤2/layered≤4/rich≤8/auto≤16; animated Look-group durations slow8..32/medium2..8/fast.25..2/auto.125..64beats. Static/off duration is ignored. Runtime schema bounds all generated layer durations for a simple strict schema; browser/runtime validation applies motion bounds to animation layers only. New programs remain rateBeats1 compatibility metadata. Existing design stays untouched until scoped acceptance; patterns/colors-only generation must not claim changed Look timing. Preferred palettes/energy/genre/character are soft guidance, not lux guarantees. Offline honors explicit palette/motion settings with bounded templates and does not interpret genre/free text. Band editor/context panel stays with AI studio and is disabled while generation is pending.
- `src/control-surface.ts` owns vendor-neutral logical slot assignment/move/swap/clear and bank names; capabilities come from adapters.ts profiles. Optional schema-1 `binding.slot:{bank,kind:button|rotary,index}` uses 1-based values; `controlSurface.bankNames` maps numeric bank keys to bounded labels. Slot uniqueness/target references/action-kind compatibility are validated. Stored generic slot bounds are wider than active profile capacity so profile changes never erase hidden placements; old bindings without slots remain unplaced.
- `control-surface-autofill.ts` plans atomic logical bank fills: selected supported banks only, all Looks, order or separate calm/movement/energetic banks, fixed optional rotary groups. Character is a local rig/pattern/timing heuristic with proposal-only overrides, not AI or saved Look metadata. Empty mode retains placements and skips already-present selected Looks; replace clears supported selected button slots, reuses unplaced IDs, preserves displaced actions, and leaves null rotary choices/outside or hidden-profile slots intact. Capacity/conflict errors return the original surface;512binding cap still applies. `ControlSurfaceAutoFill` previews before apply, invalidates on option/show changes, and commits through the editor's existing controlSurface-only validation/undo history. No hardware requests or show-schema changes.
- `ControlSurfaceEditor` is setup-only: catalog look/color/mode actions map to buttons, group intensity to rotaries. Full/Rack expose16×(8buttons+4rotaries), Compact exposes USER16buttons only (M/M and optionalDCA not implemented). Custom names/assignments persist in show packages; history is session-local, bounded20, restoring controlSurface only. Occupied moves swap if compatible, catalog replacement unplaces the displaced action, clearing preserves the binding. Drag payloads contain internal lookup keys only. No edit/selection executes a runtime command; explicit Look-preview navigation uses rehearsal state. Audio/sync settings remain secondary. There is no physical WING upload, MIDI/OSC adapter, or native capture activation behind this editor; UI must keep that gap explicit.
- `LookStudio` combines selected-Look editing and direct simulation under Ontwerp & repetitie. It renders the stored Look directly (never audition/live overrides); LookEditor embedded mode reuses group editing. A separate session-only preview BPM (30–240, default120) integrates elapsed wall time through `advancePreviewBeat`, preserving phase across tempo edits. Creative edits update renderer inputs without rebuilding WebGL; only physical scene changes rebuild it. Legacy standalone color/program auditions remain a secondary `audition` workspace. Preview selection/BPM never change Live controls; saved Look edits do change the shared Look document.
- `src/live-controls.ts` owns session-only per-group partial layer overrides and disjoint linked control sets. `livePreview` derives rendering input only; never save/export it or feed it to rehearsal. Linking merges existing sets without changing output; subsequent edits change only requested fields. Loading a group Look copies each target group's own source layer and captures the source palette. Unlink preserves current settings. General Look selection clears overrides but keeps links; import/start restoration clears both, full creative replacement clears overrides. Group actions retain blackout/safety/held beat. Existing stored masters also follow links from Live only; temporary Lookniveau is distinct. No WING hardware routing added.
- Browser-source Live group UI remains collapsed by default with changed-group count; selected-group inspector shows mixed linked values and prospective link union before applying. Browser links/overrides are session-only, bounded by current groups and discarded on reload; runtime-source state instead survives reconnect until runtime stop/fault. Missing creative references fall back to the base Look in browser helpers; runtime transport rejects unknown references before application. Shared animation spatial unions retain existing composer semantics when a group changes its program.
- `src/rehearsal.ts`: ephemeral rendering input reused by candidate previews. Following a Look preserves all layers; a palette-only override preserves fixed layer colors. Explicit standalone program/static-color auditions temporarily use all light-containing groups with haze-only groups off, ignoring legacy animation targets. Synthetic Looks are never persisted/exported/passed to live controls. Rehearsal survives navigation but resets on reload/import/start restoration; choosing/following a Look clears auditions. A newly created group referenced by a Look layer must survive stage undo.
- Future hardware adapters consume evaluated frames only; they do not influence simulation state.

## Tooling

- `StageCameraMarker` shows the simulation camera on the setup plan with a direction arrow and height/preset caption. Offstage/inset viewpoints are explicitly schematic; this is not an FOV footprint. Activation opens the existing view inspector without changing selection or show, and cancels targeting safely. `stage-camera.ts` owns shared presets and exact matching. No schema or output changes.
- Zaal/new-show camera sits 1m above the stage plane, 12m toward the audience, looking upward to1.8m (FOV48). This approximates audience eye height below a raised stage's performers; it does not change stage geometry. Saved/custom camera coordinates remain untouched: reselect Zaal to adopt this preset. Overzicht retains the elevated view.

- `LiveControlSurface` renders saved profile banks/slots in Live and reuses App's Look, mode, color-lock and linked group-master handlers. It never edits assignments or sends hardware commands. Bank selection is session-local; missing/unsupported slots stay disabled. Group masters persist, color locks remain session-only and can be released without resetting group overrides. Preview sizing is bounded independently of the controller. Rack/Full and Compact retain their Setup capabilities.
